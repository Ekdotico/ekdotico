# The processors that Ekdotico α 0.1.0 reaches

NFR-DP-03, NFR-IC-13; the processor table of §2.7 (`srs/2-functional-requirements/2.4-and-2.7-restated.md`, "Processors and agreements") at the draft register `docs-decisions@ce77557` (docs#96), where Brevo is the email service (register D206) and Scaleway is a processor for the copy of the backups alone (D118). `origin/main` of the Docs (`5ad3a94`) still names Scaleway for email. This record states what the code of this repository sends to each, which `tests/unit/processors.test.ts` holds to the code. The columns that only the owner can fill are marked **owner**.

α 0.1.0 is used by the founding team alone and sends nothing to Praktico. It reaches three of the five processors.

**Brevo.** The owner confirmed the checks of Q50 on 1 November 2026 and kept Brevo as the email service (D262). The sender is built and no test reaches Brevo: the unit tests of the sender replace `fetch`; every other run uses the sink, because the integration tests (`tests/integration/identity.ts`) and each environment of the end-to-end tests (`playwright.config.ts`, `tests/e2e/fault-page.spec.ts`, `tests/e2e/sharing.ts`, `tests/e2e/smoke.spec.ts`) set `EMAIL_TRANSPORT=sink` themselves, whatever a `.env.local` or the shell holds, and `tests/unit/processors.test.ts` fails if an end-to-end environment names a sink directory and not the sink, or names the key. **No real email is sent until the owner switches it on**, by setting `EMAIL_TRANSPORT=brevo`, `BREVO_API_KEY` and `EMAIL_FROM` on the deployment, and sends one test email to an address of their own, which is how Q74 is tested: whether Brevo rewrites a link of its plain-text email, which would pass a single-use token through its tracker. If it does, and Brevo has not turned click tracking off, no email goes to a test user. The conditions that D262 sets are the owner's, in the Brevo account, and none of them has been made yet: email previews off; a retention rule, of 30 days if the settings offer it; tracking anonymised; a written request to turn click tracking off for the account; Brevo's AI features not used; a dated copy of the terms. The application keeps no copy of any of them. The code has no client library of Brevo (`tests/unit/processors.test.ts` fails if one is added), and names its host in one file, the sender. The sink's files are on a developer's disk and a deployment writes none (storage-match.md section E, register D270); they are not a processor.

**Location (NFR-IC-13).** The build-phases limit says "the email service is in Paris". That was Scaleway's, from its documentation of 5 October 2026. For Brevo, Paris is the seat of the processor and not where the data is: the row above states what the agreement says (D262), and the sentence is not repeated (docs/plan/slice-27.md, S27-9).

## C. Not processors

Better Auth is a library inside the application, with its tables in the application's database; there is no identity processor. Cloudflare and Neon are not processors of the application once Praktico has moved to Frankfurt; the release sends nothing to Praktico. Cloudflare is a processor of the waitlist site alone, through Turnstile (section D). The checker of NFR-RE-03 is given no personal data, so it is not a processor either (build-phases).

## D. The waitlist site (`alpha.ekdoti.co`, `ekdoti.co`)

The waitlist site is a separate project (`alpha`), not the application, and its readers are not users of α 0.1.0. It is a processor table of its own. Checked from outside on 18 November 2026; the location of each is what the site's README (`Data location`) and the headers state, and is marked as such.
