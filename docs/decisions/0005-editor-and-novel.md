# 0005 — The editor: Tiptap 3, and what is taken from Novel

- **Date:** 9 October 2026, with the first slice of the editor (the document page and its collaborative editor).
- **Requirement:** NFR-IC-01 (the Editor row: "Tiptap + ProseMirror (Novel fork), Hocuspocus, Yjs"), NFR-IC-04, NFR-IC-08, NFR-IC-12; register D66 ("Novel fork" means that the editor source of Novel is taken into the repository at a recorded commit and maintained there).
- **The owner's decision of 8 October 2026 (E1):** "Take only the files the cut uses, at a named commit, ported to Tiptap 3, with the Apache-2.0 notice and a list of changes recorded; build the slash palette on Tiptap's own utility with design-package controls." Where nothing in the cut needs Novel's code, nothing is taken, and that is recorded here.

## What was taken from Novel: nothing

Novel was read at commit `fa95098e66476c466faebb8211baa5869c101a9c` of `github.com/steven-tey/novel` (18 January 2025, the head of `main` on the day; Apache-2.0), package `packages/headless`, which is the editor. `@tiptap/react` lists `@tiptap/extension-bubble-menu` and `@tiptap/extension-floating-menu` as optional dependencies, which bring `@floating-ui/dom`. Those two are installed and not imported: the build does not carry them.

**`@floating-ui/dom` (1.8.0, MIT) is carried by the build since the slash palette.** `@tiptap/suggestion` declares it as a required peer and imports it when it is loaded, for the placing of a list that the utility offers and the application does not use: the package's `OptionList` places itself. It is not a direct dependency, and the lockfile resolves the peer to the copy that was already installed. Nothing of it runs but the making of two option objects when the editor starts; it writes no style and makes no request.

**One copy of Yjs.** The lockfile holds one `yjs` (13.6.33), one `y-protocols` (1.0.7), one `lib0`, and one each of `prosemirror-model`, `prosemirror-state` and `prosemirror-view`; the provider, the collaboration extension and `@tiptap/y-tiptap` take Yjs as a peer and resolve to the one the application pins. Two copies would not fail loudly: a document made by one is not a document to the other. Check after any change to these pins: `grep "^  yjs@" pnpm-lock.yaml | sort -u` prints one line, `yjs@13.6.33:`; and in a build, the sentence Yjs prints when it is loaded twice, "Yjs was already imported", is in one file of `.next/static/chunks` and once (measured on the build of this slice).

## What is deliberately off

- **Tiptap's own Markdown input rules, and every paste rule.** The library's set is not the list of FR-ED-14 (it also takes `+`, any number before a full stop, `___`, `***`, `~~~`, a language after the fence, `__`, `_` and `==`). The editor turns on the input rules of one extension, the application's (`enableInputRules: [MARKDOWN_INPUT]`; `src/app/(app)/documents/[id]/input-rules.ts`, with the patterns in `src/lib/editor/markdown.ts`), which holds the thirteen rows of the requirement and nothing else. `enablePasteRules` stays off: FR-ED-14 is of what is typed, so pasted Markdown is text.
- **Tiptap's keyboard shortcuts that are not in FR-ED-13.** Each extension still ships its own, and twelve are not on the requirement's list: the paragraph, the three headings, the two lists, the blockquote, the code block, `Mod-e` for inline code (the requirement says `` Mod-` ``), highlight, subscript and superscript. `src/app/(app)/documents/[id]/shortcuts.ts` names them (`REMOVED`) and answers each before the library does, so the editor does nothing with the key and the browser keeps it; the same file adds `` Mod-` `` and `Mod-k`. `tests/unit/editor-keys.test.ts` lists every key the extensions bind with Ctrl, Cmd or Alt, and fails when a release of the library binds one that is neither on the requirement's list, nor a key of plain editing, nor removed.
- **Turning text into a link by typing or pasting an address, and following a link from the text being edited.** Asked for nowhere.
