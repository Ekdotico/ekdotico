## 2. The route, in the order things happen

`POST /api/documents/[id]/export/draft`, made by `documentRoute('document.export.draft', draftExport)`, so that in this order: the origin (a 403), the session's row (a 401, or the founding-team gate's 403), the document and the permission from current state (a 404 or a 403 written to the log), and only then:

1. **The lock.** One export at a time for a user: a key in Valkey set with `NX` and an expiry of twice the idle period, holding a random token. Taken first, so that a refused request is not counted against the hour. Refused: 429, `Retry-After`, the statement of section 8.
2. **The limit** of NFR-SE-07, 10 in any hour, taken with `takeLimitReturnable`. Over: the lock is released and the 429 is answered (the entry `rate_limit_reached` is written as for every limit).
3. **The work before the first byte**, each step releasing the lock and giving the count back on failure: the title and the stored state are read together, of a document that is not deleted (one deleted since the request was authorised is the 404 of every route); the state is loaded into a Yjs document and read into a tree; the rows of the images the document names are read, from this document only; the Markdown is written whole (a document is 5 MB at most, and a Markdown file is bounded at 32 MiB, after which the export fails with a fault before it begins: S21-8). A document with images and no store answers 503 before the first byte. A fault answers the one statement of every route (`fault`, which logs a class and nothing else). Nothing here answers with part of a file.
4. **The response**: 200, `application/zip`, `Content-Disposition: attachment`, `Cache-Control: no-store`, no `Content-Length`, a body that is a stream (section 4). The count of the hour is kept from here on.

**Authorisation is decided once, at step 0.** The role and the permission set are read from current state for this request. A collaborator removed while an export is under way is not cut off (S21-5).

**Where the lock is released.** In one function that runs once, whatever ended the response: the last byte, a fault in the store, an idle time-out, the client's disconnect (the stream is cancelled), and every failure before the stream exists. The key's expiry is the answer to a process that dies: it is renewed while bytes move (at most four times in its period) and gone 60 seconds after the last renewal.

## 4. The archive

**Layout.** `<name>.md` first, then `images/001.png`, `images/002.jpg`, ... in the order of the images' first appearance in the document. The name of an image file is its place, padded to three digits (more when there are more than 999), and the extension of its stored type: `png`, `jpg` (for `image/jpeg`), `gif`, `webp`. An image that appears twice in the document is one file and two references. An image that was uploaded and no longer appears is not in the archive (A99). No directory entries. A document without images is the Markdown file alone.

**The writer** produces: for each entry a local header (version 20, flags: data descriptor and UTF-8 names, stored), the bytes, and the descriptor (`PK\7\8`, CRC-32, sizes); then the central directory and the end record. No compression: the images are stored as they are (FR-EX-36), the text is small. No ZIP64: an entry or the archive past 4 GiB, or more than 65,535 entries, is refused with a fault, none of which a document can reach (100 MB of images; at most 5,000 blocks).

**Path safety**, held by the writer itself and not by its caller. A name is refused (and the export fails with a fault) if it is empty, longer than 255 bytes, begins with `/`, contains `\`, a control character, a NUL, a segment that is empty, `.` or `..`, or a drive prefix (`^[A-Za-z]:`); and if it repeats an earlier name, compared without regard to case. The names the code makes are `<name>.md` and `images/NNN.ext` and can be none of these, since `<name>` has had its separators and its pairs of full stops removed. The writer's rule is a second, independent line.

**Bounded memory.** The body is a stream with a queue of one chunk. The Markdown is in memory once (5 MB of document, 32 MiB at most written). An image is read as a stream and passed on in the chunks the store gives (64 KiB at most is asked for); its size is checked as it passes against the size the database holds for it, and a store that sends more or fewer bytes ends the export in an abort. Nothing is written to disk and nothing is buffered beyond one chunk and the Markdown.

**Idle time-out.** A timer of `EXPORT_IDLE_SECONDS` (30) is restarted each time the response makes progress: the consumer asks for the next chunk (so it has taken the last), and a chunk is queued. When it fires, the stream is errored, the object read is aborted, the lock is released, and the timer is gone, whichever side stopped: a store that stops answering, or a client that never reads and so leaves one chunk queued and no request for the next. Where the stop is on the store's side, or is a fault, Next.js 16.4.3 turns the error into a destroyed connection, and the browser reports a failed download (shown on the built application, with an object that is not there). **Where the stop is a client that is connected and has stopped reading, it does not** (S21-9): the framework's writer is waiting for the socket to drain, and an abort waits behind that wait, so the socket stays open, holding one chunk of 64 KiB, until the client reads on (and then meets a response that ends as a failure and not as a file, which the built application shows too) or goes, or until the proxy in front closes it (`docs/operations/deployment.md`, items 13 and 14).

**After the first byte**, a failure (an object that cannot be read, a size that does not match, an idle time-out) errors the stream: the connection is aborted and the response is not ended in an orderly way. Before it, the answer is a statement in the one error shape and no file.

## 5. The name rule

`exportName(title)`, FR-EX-36 to the letter, in this order: remove `/` and `\` (path separators); remove every run of two or more full stops; remove control characters (Unicode `Cc`, and the bidirectional controls U+202A to U+202E and U+2066 to U+2069, which could make `x.zip` read as another name: S21-2); remove quotation marks (`"`, and the typographic double marks U+201C to U+201F: S21-2); cut to `EXPORT_NAME_MAX_CHARS` (100) characters, by code point, so that no pair is split; and if what is left is empty, or only white space, the fixed name `document`. The archive is `<name>.zip` and the file inside `<name>.md`, from the same stem.

The header: `attachment; filename="<ASCII form>"; filename*=UTF-8''<percent-encoded>`. The ASCII form replaces every character outside printable ASCII, and `%`, with `_`. The encoded form leaves only the characters RFC 5987 calls attr-char and encodes the rest, `'`, `(`, `)` and `*` among them. A title cannot reach either form with a quotation mark, a line break, or a semicolon that ends the parameter (a semicolon is inside quotes and in the encoded form is `%3B`).

Left as the rule has it: `: * ? < > |` and the Windows reserved names are not removed (S21-2).

## 6. The Markdown

CommonMark with the GitHub extensions the table needs (pipe tables, strikethrough) and the footnotes of GitHub and Pandoc (`[^n]`). Written lines are LF.

**Front matter**, first, and nothing before it:

```
---
title: "<the title, escaped as a YAML double-quoted string>"
date: 2026-10-26
id: <the document's UUID>
draft: true
---
```

The title: `\` and `"` escaped, every control character, U+0085, U+2028, U+2029, U+FEFF and lone surrogates written as `\uXXXX`, so that a title cannot end the string, add a key, or fold a line; every other code point is written as it is. The date is the day of the export, UTC. No person's name, no email address, no user identifier. Then, below a blank line, the note: the fixed sentence of FR-EX-02, verbatim, as a blockquote: `> Draft export — not a provenance-sealed document.`

**Escaping** (NFR-SE-08, NFR-I18-03, FR-EX-36 "a character of the user's text that Markdown would read as syntax is escaped"). In text, always: `\` `` ` `` `*` `_` `[` `]` `<` `|` `~` `$` with a backslash, and `&` where it begins what reads as a character reference. At the start of a line: `#`, `>`, `-`, `+`, `=`, the full stop or bracket after digits, and a leading space or tab (written as `&#32;` or `&#9;`, so that four are not an indented code block). Nothing is removed and nothing is turned into an entity but those two. A character the user typed is always in the output as it is or after a backslash.

**Footnote definitions** after the body, one blank line before the first. A line break inside an entry is a backslash and the next line indented by four spaces.

## 7. The control

On the document page, in the header beside "Sharing": a button from `@ekdotico/domico` (`Button`, `pending`, `pendingLabel`), shown when the role holds `document.export.draft`. It `fetch`es the route with `POST`; on success it reads the body to a `Blob`, names it from `Content-Disposition`, and has the browser save it through an object URL; on a refusal it shows the route's own statement in a `FormFault` (the pattern of every page), focused; on a body that fails to arrive it says so in words of its own. A status region (`role="status"`) states that the export is under way (within 500 ms: NFR-PE-01) and that it is ready. While it is under way the button is not available (the server refuses a second in any case).

The page re-reads the server when the editor is told that the role or the permissions changed (`router.refresh()` on the notice's counter), so the control appears or goes with the change.

**Domico.** The control uses `Button`, `FormFault`, `Cluster`, `Stack` and the page's classes only; nothing is drawn in this repository.
