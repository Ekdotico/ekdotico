## 7. Stopped items: rows for the register

Each is written for the owner to add. None stops the work of this slice; each stops something that is owed before the first test user is admitted.

1. **Which row of §2.7 covers `Workspace`, `DocumentCollaborator`, the migration table and the files of the email sink.** What is open: NFR-DP-02 asks every table to be matched to a row of the retention schedule, and four stores the release creates have none. `Workspace` (an identifier, a type, the owner's identifier) and `_prisma_migrations` (the names and checksums of migrations) hold no personal field; `DocumentCollaborator` holds two identifiers and a role, for the document's lifetime, and is deleted with the document and when an account is deleted (FR-AU-58 (f)); the files of the email sink hold an address and may hold a single-use link, are written on the host's disk by every deployment that sets `EMAIL_TRANSPORT=sink` (the only value there is), and no timer deletes them. Recommended answer: add to the schedule one row for the collaborator's role and one sentence for tables without a personal field ("the retention of the row they belong to"), and for the sink either a retention with a timer that deletes the files (7 days, the age of a link that has lapsed twice over) or, away from localhost, the refusal to start with the sink until Brevo's checks are made, so that a deployment writes none. Alternatives: the files are deleted by hand by the owner and the row says so; the sink writes nothing on a deployment and an invitation is created without an email until Q50 is closed; the sink's directory is on a volume that is wiped at each deployment. Who decides: the owner. Blocks α 0.1.0: it blocks the admission of the first test user (NFR-DP-02 asks the match before that), and it does not block the build.
2. **Whether the credential for the bucket of the copies can be made to add and not overwrite, on Scaleway.** What is open: NFR-RE-10 and A28 (assumed) say the host's credential "can add an object and can neither delete nor overwrite one". The protocol has no right to put an object only where none exists; an overwrite of a key is a put. The script gives every copy a key of its own and asks the store not to replace (`If-None-Match: *`), which protects against the script's own fault and not against a host that is taken over and a credential that may put. Recommended answer: versioning on the bucket, a policy that refuses deletion of any version, and the 4 weeks as a rule that expires versions as well as current objects (so an overwrite keeps the original); read Scaleway's documentation for each of the three before the bucket is made, and record what it states in procedure 6. Alternatives: Object Lock in compliance mode for 4 weeks; a second credential in a second account that only the owner holds, for the expiry. Who decides: the owner. Blocks α 0.1.0: the copy is a criterion of the first admission (NFR-RE-10); the rule is a property of the bucket, which the owner makes.
3. **`AUTH_SECRET` is two secrets of NFR-SE-17 (e) in one value, and the library's way of rotating one without loss is refused by the configuration.** What is open: see S27-6. Recommended answer: keep one value and rotate with `scripts/rotate-auth-secret.ts` (built here, tested), which signs everyone out. Alternatives: configure the library's versioned secrets (`BETTER_AUTH_SECRETS`), which rotates without signing anyone out but needs the decision record NFR-IC-01 asks for and settles the refusal of the variable; or hold two values (one for cookies, one for the second factor's key) so that each rotates on its own. Who decides: the owner. Blocks α 0.1.0: no. The rotation procedure is recorded as NFR-SE-17 (e) asks, before the first admission, and works as it stands.
4. **The limit of NFR-IC-13 in the build-phases page names Paris for the email service.** See S27-9. Recommended answer: the sentence reads "every host the release runs on is in FRA1; the location of the email service is recorded in §2.7 once Q50 is closed". Alternative: none. Who decides: the owner, in the Docs. Blocks α 0.1.0: no.
