# The reader's view: a browser that cannot edit shows what the schema can show

Written on 18 October 2026 against Docs commit `f4ec614`, and the draft register at `docs-decisions@2efc42f` (D185, D190, Q45, D122). Answers row S13-1 of `slice-13.md` §7, which the owner answered the same day: "A separate editor slice: the reader's browser shows what the schema can show and writes nothing (D185)."

**Built.** In a browser that holds no permission to edit content (`canEdit` false of `page.tsx`: the Viewer, and the Reviewer when it is offered) the editor shows what the schema can show of the document, built locally from the shared document, and writes nothing to the shared document: no repair, no update, ever. When an editor's browser repairs the document, the reader's view follows. The editor's own path (`holdBinding`, `mend`, `unstray`, and everything of the Collaboration extension) is not changed.

## 2. What happens today

A reader's editor is built with the Collaboration extension, whose binding (`ProsemirrorBinding` of `@tiptap/y-tiptap`) builds the text from the shared document and writes it back. `holdBinding` withholds its own mending where `view.editable` is false, but three things remain:

1. **Text standing directly in the fragment** is not built by the library: `_forceRerender` calls `createNodeFromYElement` on it and throws. `unstray` can take it out only where the browser writes, so a reader's `held` catches the fault and tells `unshown`: "This document could not be shown".
2. **The library's own writes are not the mending's.** `createNodeFromYElement` and `createTextNodesFromYText` delete from the shared document an element or text that fails to build (origin `ySyncPluginKey`), `_prosemirrorChanged` writes the text back at every change of the view (a click in the text is one), and two adjacent texts of the same client are merged in the shared document. None of these passes through `mend`, `unstray` or the `MEND` origin, which is all the existing tests count. Each would leave a reader's page saying "Syncing" for good.
3. The server discards what a read-only connection sends, so none of this reaches anyone. What it does is hold the reader's tab in a state the reader did not cause.

So guarding more functions of the binding would be a list of what the library writes, and an upgrade could add to it. The reader's browser is built without the binding instead.

## 3. Design

- `extensions(document, unshown, noRoom, unrepairable, reads)`: where `reads` is true the Collaboration extension is replaced by `ReaderView`, and the editor has no sync plugin, no undo plugin and no binding. Nothing in it can write to the shared document: there is nothing to write with. `editor.tsx` passes `reads = !canEdit`.
- `shownOf(shared, schema)`: the text of what the schema can show. A copy of the shared document is made (`Y.applyUpdate` of its state into a new `Y.Doc`), what stands directly in the copy where it cannot (`strays`, the editor's own rule) is deleted from the copy, and the text is made of the copy by the library's own function (`yXmlFragmentToProseMirrorRootNode`) over the closed schema (`closeSchema`): so the reader is shown what an editor's browser shows once it has mended, by the same making. Until an editor writes them, the reader omits what an editor's repair also adds (the paragraph at the end of a document that the schema requires, the fixes of a table); the two converge once the editor's repair arrives. A document left with nothing is the schema's empty document. The copy is made once and fed each update of the shared document (`shownCopy`); where taking out what cannot stand, or the library's making, wrote anything to it, it is put away and the next text is made of a new copy, so that it never drifts from the shared document. A fault of the making (quotes nested ten thousand deep) is `unshown`, as for an editor.
- `followShared(view, document, unshown)`: makes the text once, and again after the updates of the shared document, whoever sent them, at most once in `max(100 ms, 4 times what the last cost)`: the first at once, and a last one after the rest. The change to the view is the smallest that makes it equal (`findDiffStart`, `findDiffEnd`), so a selection in a part that did not change stays; it carries the binding's meta, so that `mayApply` and the limits treat it as what arrives and not as the writer's own, and it is not added to any history. Where the smallest change does not give the text, the whole text is replaced.
- `ReaderView` calls `followShared` when the editor is created and stops it when it is destroyed.

## 4. The cases

Each is built in a document that a reader opens with it, and arrives to a reader's open page; each is tested with the reader's browser writing nothing, showing what remains, and following the repair.

| Case                                                       | What a reader is shown                                                                        |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Text directly in the document                              | The rest of the document                                                                      |
| A row, a cell, a table, a caption, an item, directly in it | The rest                                                                                      |
| A node of no type, at any depth                            | The rest of its parent                                                                        |
| A mark of no type; what is no text in a text               | The text without them                                                                         |
| An emptied element (a quote with nothing in it)            | The element with what the schema must put in it (one paragraph)                               |
| A table with a row, a cell or a nested table past a bound  | The table as the bound leaves it                                                              |
| A document with nothing but strays                         | The schema's empty document                                                                   |
| A document past a limit of tables or blocks                | All of it (nothing is left out for a limit), and no statement of the limit (RV-2, 18 October) |
| A document that cannot be built                            | "This document could not be shown", unchanged (D122)                                          |

## 5. Tests (each fails when its rule is broken)

Unit, `tests/unit/editor-schema.test.ts` (it holds the helpers that make hostile documents and the editor's own harness):

- (a) **Writes nothing.** For every case above, a reader's page is opened on the document, and then the document changes by what arrives from a peer; every update that the shared document emits with an origin other than the peer's is counted, and so are the bytes of the shared document before and after. Both stay at zero and equal. The editor's view is also changed as a click changes it, and still nothing is written. Weakened by: making the text from the shared document and not from a copy.
- (b) **Shows what the schema can show.** The text is the one that an editor's browser holds for the same document, case by case, and the page is not told `unshown`. Weakened by: leaving out the removal of strays from the copy, which brings back the statement.
- (c) **Follows the repair.** A reader's page and an editor's page on two copies of one document, joined by what each sends. The editor mends; what it writes reaches the reader; the reader's text is the same as before and holds what the editor then types. Weakened by: not listening to the shared document.
- The editor of a reader has no binding: no extension of that name, no sync plugin in its state.
- The editor path is as it was: the existing tests of `holdBinding` pass without change.

End to end, `tests/e2e/editor.spec.ts`, with a real Viewer (accepted through an invitation): a document that holds text standing directly in it, written by a client that is no editor, is opened by the Viewer, who sees the paragraphs and not the statement; clicks in the text; and sends no update (the frames of its socket are decoded: no update message, and the answer to the server's state is the empty update). The Owner then opens it, and the stray text leaves the shared document; the Viewer's text is unchanged, and follows what the Owner then types.

## 8. Not done, and said plainly

- No browser other than Chromium; no screen reader run; no phone width (the surface is the editor's own, unchanged).
- The cost of the text of a large document: it is made again at each text that is shown, as the binding makes it again at each change (`_typeChanged`), at most once in 100 ms or four times its cost. The copy of the document is made once, and fed. Where the document holds something that is taken out of the copy, the copy is made again for each text (a tenth of a second for 5 MB, as measured in the review). A measurement in a browser is not made here.
- The Reviewer holds no role that is offered (D56), so no Reviewer is tested: the path is `canEdit` false, which the Viewer holds.
